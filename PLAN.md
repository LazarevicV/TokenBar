# TokenBar — Implementation Plan

A small macOS menu-bar-only app that shows the current rate-limit usage (session window + weekly window + reset time) for **Claude** (Claude Code / claude.ai subscription) and **Codex** (ChatGPT subscription). Usage comes from the **account-side usage APIs**, not from local chat logs.

This document is written so it can be handed to implementing agents. Sections marked **VERIFIED** were confirmed by live probes on this machine on 2026-09-13.

---

## 1. Goals / non-goals

**Goals**
- Menu bar icon (no Dock icon, no main window). Clicking opens a popover with the layout in §5.
- Show for each provider: session-window %, weekly-window %, and the reset time of the *session* window (plus weekly reset on hover/secondary line).
- Refresh automatically on a timer and on demand.
- Zero-config first run: reuse the credentials that `claude` and `codex` CLIs already store locally.
- Handle "not logged in", "token expired", "offline", and "API error" gracefully.

**Non-goals (v1)**
- No token counting, cost estimation, or reading of local session/JSONL files.
- No own OAuth login flow (see §3.4 for the optional v2 path).
- No support for other providers (Cursor, Gemini, Copilot…). Keep the provider abstraction open so it could be added later.
- No App Store distribution. Direct build / `.app` bundle, optionally notarized later.

**Prior art**: [steipete/CodexBar](https://github.com/steipete/CodexBar) does this for 60+ providers. We deliberately build a much smaller, two-provider app. Its source is a useful reference for endpoint quirks if something breaks.

## 2. Tech stack

| Concern | Choice | Reason |
|---|---|---|
| Language / UI | Swift 6, SwiftUI, `MenuBarExtra` with `.window` style | Native, tiny binary, no Electron. Machine has Swift 6.4 / Xcode toolchain. |
| Min macOS | 14 (Sonoma) | `MenuBarExtra(.window)` is stable there; dev machine is on macOS 26. |
| Build | Swift Package (`swift build`) + a small script that assembles the `.app` bundle, **or** an Xcode project. Recommendation: **Xcode project generated by XcodeGen** or a hand-written `.xcodeproj` so `LSUIElement`, entitlements and signing are trivial. | Menu-bar apps need `Info.plist` keys; an SPM executable alone can't carry them cleanly. |
| Networking | `URLSession` async/await | No dependencies. |
| Persistence | `UserDefaults` for settings (refresh interval, launch at login); no credential storage in v1. | We never write credentials. |
| Keychain read | `Security.framework` `SecItemCopyMatching` | Read Claude Code's keychain item. |
| Launch at login | `SMAppService.mainApp` | Modern API, no helper app. |

No third-party packages required.

## 3. Data sources (the core of the app)

### 3.1 Claude — **VERIFIED**

**Credential location**: macOS login Keychain, generic password item
- service: `Claude Code-credentials`
- account: current username
- The secret is a JSON blob:

```json
{
  "claudeAiOauth": {
    "accessToken": "sk-ant-oat01-…",
    "refreshToken": "sk-ant-ort01-…",
    "expiresAt": 1789329289644,            // ms since epoch
    "refreshTokenExpiresAt": …,
    "scopes": ["user:profile", "user:inference", …],
    "subscriptionType": "pro",
    "rateLimitTier": "default_claude_ai"
  }
}
```

Fallback location if Keychain item is absent: `~/.claude/.credentials.json` (same JSON shape; used on Linux and older versions).

Shell equivalent for debugging:
```
security find-generic-password -s "Claude Code-credentials" -w
```

**Usage endpoint**
```
GET https://api.anthropic.com/api/oauth/usage
Authorization: Bearer <accessToken>
anthropic-beta: oauth-2025-04-20
User-Agent: TokenBar/<version>
```

Response (trimmed to the fields we use):
```json
{
  "five_hour": { "utilization": 5.0,  "resets_at": "2026-09-13T16:10:00.944794+00:00" },
  "seven_day": { "utilization": 0.0,  "resets_at": "2026-09-18T20:00:00.944817+00:00" },
  "seven_day_opus":   null,
  "seven_day_sonnet": null,
  "extra_usage": { "is_enabled": true, "utilization": 0.21, "used_credits": 21.0, "monthly_limit": 9900, "currency": "USD" },
  "limits": [
    { "kind": "session",    "group": "session", "percent": 5, "severity": "normal", "resets_at": "…", "is_active": true },
    { "kind": "weekly_all", "group": "weekly",  "percent": 0, "severity": "normal", "resets_at": "…", "is_active": false }
  ]
}
```

Mapping:
- Session % → `five_hour.utilization` (0–100, float). Reset → `five_hour.resets_at` (ISO-8601 with fractional seconds + offset).
- Weekly % → `seven_day.utilization`. Reset → `seven_day.resets_at`.
- Treat any window object that is `null` as "not applicable" and hide it. Many extra keys exist (`seven_day_opus`, `nimbus_quill`, …); **decode leniently** — unknown keys must be ignored and nullable objects tolerated.
- Optional secondary info: `extra_usage` (paid overage credits) — show only if `is_enabled` and worth a small line. Not required for v1.

**Profile endpoint** (optional, for showing plan/name in the popover):
```
GET https://api.anthropic.com/api/oauth/profile   (same headers)
→ { "account": { "full_name": …, "display_name": … }, "organization": { … } }
```

**Token expiry**: `expiresAt` is ms-epoch. Access tokens are long-lived (the current one expires in months). See §3.3 for refresh policy.

### 3.2 Codex — **VERIFIED**

**Credential location**: `~/.codex/auth.json` (mode 0600), shape:
```json
{
  "auth_mode": "chatgpt",           // or "apikey"
  "OPENAI_API_KEY": null,
  "tokens": {
    "id_token": "<JWT>",
    "access_token": "<JWT>",
    "refresh_token": "…",
    "account_id": "e381c8b8-…"
  },
  "last_refresh": "2026-09-09T08:15:56.367178Z"
}
```
Respect `CODEX_HOME` env var if set (defaults to `~/.codex`).

If `auth_mode == "apikey"` the usage endpoint is not available → show "Sign in with ChatGPT in Codex to see limits".

**Usage endpoint**
```
GET https://chatgpt.com/backend-api/wham/usage
Authorization: Bearer <tokens.access_token>
ChatGPT-Account-Id: <tokens.account_id>
User-Agent: TokenBar/<version>
```

Response (trimmed):
```json
{
  "email": "…",
  "plan_type": "plus",
  "rate_limit": {
    "allowed": true,
    "limit_reached": false,
    "primary_window":   { "used_percent": 54, "limit_window_seconds": 18000,  "reset_after_seconds": 11325,  "reset_at": 1789313353 },
    "secondary_window": { "used_percent": 8,  "limit_window_seconds": 604800, "reset_after_seconds": 509342, "reset_at": 1789811371 }
  },
  "credits": { "has_credits": false, "balance": "0" },
  "rate_limit_reset_credits": { "available_count": 2, "applicable_available_count": 0 }
}
```

Mapping:
- Session % → `rate_limit.primary_window.used_percent` (int). Reset → `primary_window.reset_at` (**seconds** since epoch; note the unit differs from Claude's ISO strings and from the Claude keychain's ms).
- Weekly % → `rate_limit.secondary_window.used_percent`. Reset → `secondary_window.reset_at`.
- Don't hard-code "5h"/"7d": derive labels from `limit_window_seconds` (18000 → "5h", 604800 → "week"). Either window may be `null` on some plans.
- The `id_token` JWT payload has `https://api.openai.com/auth.chatgpt_plan_type` if we want the plan without an extra call; `plan_type` in the usage response is simpler.

### 3.3 Token lifecycle policy — **important design decision**

**Never refresh tokens ourselves in v1.** Both providers rotate refresh tokens; if TokenBar redeems the shared refresh token, the CLI's stored refresh token can become invalid and the user gets logged out of `claude`/`codex`. Other tools hit exactly this (see antiburn issue #442, 9router #1663).

Policy:
1. Read credentials fresh from disk/Keychain on **every** refresh cycle (cheap; the CLIs rewrite them when they refresh).
2. Codex access tokens are short-lived (hours). If we get `401`, re-read `auth.json`; if still 401, show "Token expired — run `codex` once to refresh" with a button that opens Terminal running `codex login status` or just `codex`. (Running `codex` triggers its own refresh.)
3. Claude access tokens are long-lived. On `401`, show "Run `claude` to re-authenticate".
4. Optional, behind a hidden setting, later: shell out to the CLI (`codex login status`) which forces the CLI to refresh using its own code path. Still no in-process refresh.

Reference values in case the in-process refresh path is ever needed (v2, own-login mode only):
- Claude: `POST https://platform.claude.com/v1/oauth/token` (form-encoded), `client_id=9d1c250a-e61b-44d9-88ed-5944d1962f5e`, `grant_type=refresh_token`.
- Codex: `POST https://auth.openai.com/oauth/token` (JSON), `client_id=app_EMoamEEZ73f0CkXaXp7hrann`, `grant_type=refresh_token`.

### 3.4 v2 option: app-owned login

If the user wants the app fully independent of the CLIs, implement PKCE OAuth for both providers and store the app's **own** token set in Keychain under a TokenBar service name. This is a separate session on each account, so refresh rotation doesn't collide with the CLIs. Out of scope for v1; keep `CredentialSource` as a protocol so this slots in.

## 4. Architecture

```
TokenBar/
├── App/
│   ├── TokenBarApp.swift          // @main, MenuBarExtra(.window), AppState injection
│   └── Info.plist                 // LSUIElement = YES (no Dock icon)
├── Core/
│   ├── Models/
│   │   ├── UsageWindow.swift      // percent: Double, resetsAt: Date, label: String
│   │   ├── ProviderUsage.swift    // provider, session: UsageWindow?, weekly: UsageWindow?, plan: String?, extras
│   │   └── ProviderStatus.swift   // enum: .ok(ProviderUsage) | .notLoggedIn | .tokenExpired | .error(String) | .loading
│   ├── Providers/
│   │   ├── UsageProvider.swift    // protocol { id, displayName, fetch() async throws -> ProviderUsage }
│   │   ├── ClaudeProvider.swift   // Keychain read + /api/oauth/usage
│   │   └── CodexProvider.swift    // auth.json read + /backend-api/wham/usage
│   ├── Credentials/
│   │   ├── KeychainReader.swift   // SecItemCopyMatching wrapper
│   │   ├── ClaudeCredentials.swift
│   │   └── CodexCredentials.swift
│   ├── UsageStore.swift           // @Observable; holds [ProviderID: ProviderStatus]; timer; refreshAll()
│   └── Settings.swift             // refresh interval, launch-at-login, show % in menu bar icon
├── UI/
│   ├── PopoverView.swift          // the layout in §5
│   ├── ProviderSectionView.swift
│   ├── UsageBarView.swift         // ██████░░░░ style bar (SwiftUI shapes, not text glyphs)
│   ├── MenuBarLabel.swift         // icon + optional compact "68%" text
│   └── SettingsView.swift         // small sheet / window
└── Tests/
    ├── ClaudeUsageDecodingTests.swift   // decode fixtures captured from the live API (redacted)
    ├── CodexUsageDecodingTests.swift
    └── ResetFormattingTests.swift
```

Key behaviours:
- `UsageStore.refreshAll()` fetches providers **concurrently** (`async let` / `TaskGroup`), each failing independently. One provider's failure must never blank the other.
- Refresh triggers: app launch, timer (default 60 s while popover closed, 15 s while open), popover open, manual ⟳ button, system wake (`NSWorkspace.didWakeNotification`).
- Keep the last good `ProviderUsage` and show it greyed with "stale · 5 min ago" if a refresh fails.
- All network calls: 10 s timeout, no retries beyond one immediate retry on transport error.
- Never log tokens. Log only status codes and response *keys* in debug builds.

## 5. UI spec

Popover (≈ 280 pt wide), monospaced-friendly alignment:

```
TokenBar                              ⟳  ⚙

Claude                            Pro
Current session    ███████░░░  68%
Weekly             ████░░░░░░  41%
Resets             Mon 14:00

Codex                            Plus
Current session    █████░░░░░  53%
Weekly             ██░░░░░░░░  24%
Resets             Tue 09:00

Updated 12 s ago                  Quit
```

Rules:
- **Bar**: 10 segments, filled count = `round(percent / 10)`. Draw with SwiftUI `Capsule`/`Rectangle` in an `HStack`, not the `█░` characters (font-dependent rendering). Colour: default accent < 70 %, orange 70–89 %, red ≥ 90 %. Use `severity` from Claude's `limits[]` when present.
- **Resets** line shows the *session* window's reset. Show weekly reset as a tooltip/secondary caption ("weekly resets Fri 22:00"). Format: if < 24 h away → "in 2h 15m"; else weekday + local time ("Mon 14:00"). Use the user's locale and time zone.
- Plan badge (`Pro`, `Plus`, `Max`, `Team`) top-right of each section, from `subscriptionType` / `plan_type`.
- Error states replace the two bars with one line + an action button:
  - Not logged in: "Not signed in · open `claude` / `codex` to sign in"
  - Token expired: "Session expired · run `codex` to refresh" (button: open Terminal)
  - Network: "Offline · showing data from 3 min ago"
- Menu bar item: SF Symbol (e.g. `gauge.with.dots.needle.33percent`) plus optional compact text showing the **highest** session % across providers (setting, default on): `◔ 68%`. Turn the text orange/red at thresholds.
- Settings (⚙): refresh interval (30 s / 1 min / 5 min), launch at login, show % in menu bar, which providers are enabled.
- Right-click / ⌥-click on the icon: quick menu with Refresh, Settings, Quit (nice-to-have).

## 6. Milestones (each is a self-contained task for an agent)

1. **Scaffold** — Xcode project (or XcodeGen `project.yml`), `LSUIElement`, `MenuBarExtra(.window)` showing static placeholder text. `xcodebuild` from CLI succeeds; app appears in the menu bar. Add `.gitignore`, `git init`.
2. **Credentials** — `KeychainReader`, `ClaudeCredentials.load()`, `CodexCredentials.load()` with the fallbacks in §3. Unit tests with fixture JSON. Never write to these locations.
3. **Providers** — `ClaudeProvider` and `CodexProvider` implementing `UsageProvider`; lenient `Codable` models; decoding tests against redacted fixtures captured from the live responses in §3 (the agent should capture fresh ones with the `curl` commands above and redact ids/emails).
4. **Store + refresh loop** — `UsageStore`, concurrent fetch, timer, wake notification, stale handling, error classification (401 → tokenExpired, missing creds → notLoggedIn, else → error).
5. **UI** — Popover per §5, bar component, reset formatting (with tests for the "in 2h" vs "Mon 14:00" switch and time-zone handling), error states.
6. **Settings + polish** — Settings sheet, launch at login (`SMAppService`), menu-bar % text, thresholds/colours, dark mode check, VoiceOver labels on bars.
7. **Packaging** — `make build` script producing `TokenBar.app`; ad-hoc signing; optional Developer ID signing + notarization later; README with install steps.

Suggested order: 1 → 2+3 in parallel → 4 → 5 → 6 → 7. Milestones 2/3 and 5 can be built against the models alone, so they parallelise well.

## 7. Edge cases & gotchas checklist

- Claude `resets_at` has 6-digit fractional seconds + `+00:00`; `ISO8601DateFormatter` needs `.withFractionalSeconds`. Write a custom decoder that tries with and without fractional seconds.
- Claude `expiresAt` is **milliseconds**; Codex `reset_at` is **seconds**.
- Claude window objects can be `null` (e.g. `seven_day_opus: null`) — decode as optionals; unknown top-level keys must not break decoding (the response has many experimental keys).
- Codex `primary_window`/`secondary_window` may be `null`; `rate_limit` may be absent for API-key auth.
- Codex `auth.json` may be rewritten mid-read by the CLI — read the whole file, then parse; on parse failure keep last good state and retry next tick.
- Multiple Keychain items can match; take the first with a valid JSON secret. Keychain read from an unsigned/ad-hoc app is fine because the item is a generic password created by another process **but** the user may get a one-time "TokenBar wants to access…" prompt — document this; choose *Always Allow*.
- Sandboxing: **do not** enable App Sandbox in v1 (it would block reading `~/.codex/auth.json` and the login keychain item). Note this in the README.
- Time-zone: reset dates are UTC; format in local TZ. Test with a fixed TZ in unit tests.
- Rate-limit our own polling: don't poll faster than every 15 s; both endpoints are unofficial and CodexBar users have seen `429`s on aggressive polling. Back off exponentially on 429/5xx (max 10 min).
- Both endpoints are **undocumented / unofficial**. Isolate them behind the provider protocol, keep the raw JSON in the error message on decode failure (redacted), and make the User-Agent identifiable.
- Handle `limit_reached: true` / `allowed: false` (Codex) and `severity != "normal"` (Claude) by showing the bar full and red with "Limit reached · resets Mon 14:00".

## 8. Security notes

- Tokens are read into memory only for the duration of a request; never persisted, logged, or sent anywhere except the provider's own API host (`api.anthropic.com`, `chatgpt.com`).
- No analytics, no crash reporting in v1.
- `.gitignore` must exclude any captured fixture files that are not redacted; add a `fixtures/README` explaining what to strip (`email`, `user_id`, `account_id`, `uuid`, names, tokens).

## 9. Quick manual verification commands (for agents)

```sh
# Claude usage
TOK=$(security find-generic-password -s "Claude Code-credentials" -w | python3 -c "import json,sys;print(json.load(sys.stdin)['claudeAiOauth']['accessToken'])")
curl -s https://api.anthropic.com/api/oauth/usage -H "Authorization: Bearer $TOK" -H "anthropic-beta: oauth-2025-04-20" | python3 -m json.tool

# Codex usage
AT=$(python3 -c "import json;print(json.load(open('$HOME/.codex/auth.json'))['tokens']['access_token'])")
ACC=$(python3 -c "import json;print(json.load(open('$HOME/.codex/auth.json'))['tokens']['account_id'])")
curl -s https://chatgpt.com/backend-api/wham/usage -H "Authorization: Bearer $AT" -H "ChatGPT-Account-Id: $ACC" | python3 -m json.tool
```

Both returned HTTP 200 on 2026-09-13 with the shapes shown in §3.
